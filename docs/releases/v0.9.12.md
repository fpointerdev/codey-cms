# CodeY CMS 0.9.12

CodeY CMS 0.9.12 makes storage and transactional email easier to operate from
the dashboard, while improving the daily visual-builder workflow. Existing
sites remain compatible and continue to receive signed updates without asking
site owners to select a CMS version.

## Highlights

- Adds dashboard-managed Local, Amazon S3, and Cloudflare R2 storage with
  encrypted, write-only credentials and connection testing before activation.
- Keeps existing media reachable through the stable upload route and waits for
  in-flight media operations before switching storage providers.
- Adds SMTP alongside Resend, Postmark, and generic HTTPS transactional email,
  with production DNS validation, pinned connections, encrypted passwords, and
  stale-test protection.
- Uses the current patched SMTP transport release and keeps file and URL access
  disabled for generated email messages.
- Makes backup jobs follow the active dashboard-managed storage provider while
  preserving deployment-owned object prefixes and off-site protection checks.
- Adds an optional compiled storefront directory for teams that ship a custom
  theme, while preserving authenticated admin, API, media, and SEO behavior.
- Improves builder copy and paste, structured content fields, media handling,
  modal focus management, responsive preview controls, and compact-screen
  editing.
- Preserves legacy refresh sessions during development `db push` workflows and
  keeps production migrations on the existing `migrate deploy` path.

## Compatibility

- WebsiteSpec, builder, and exported-site acceptance contracts remain at
  version `1.0`.
- Existing CodeY-generated sites and CodeY CMS `v0.9.11` data remain compatible.
- No existing content, media key, or provider credential is rewritten during
  upgrade.
- Payment, email, and storage credentials remain encrypted site-owner settings;
  they are not added to WebsiteSpec or generated environment files.
- The signed runtime metadata retains the `v0.9.7` automatic-update bootstrap
  floor.

## Database And Environment

This release adds no database migration and no required environment variable.
`CUSTOM_STOREFRONT_DIR` is optional and should point only to a trusted compiled
theme included by the deployment owner. Existing environment-based storage and
email values remain valid bootstrap fallbacks.

## Upgrade And Recovery Notes

Create a verified backup, then update from the dashboard or start the new
self-host package. Existing database, media, backup, secret, and release-history
volumes are reused. Storage-provider changes copy media referenced by the stable
upload route before the new provider becomes active; keep the source provider
available until the dashboard confirms the switch.
