# CodeY CMS 1.2.0

CodeY CMS 1.2.0 makes structured content portable and introduces a governed,
declarative extension lifecycle without allowing third-party server code to run
inside the CMS.

## Highlights

- Adds a checksum-pinned extension catalog with install, update, planning, and
  non-destructive disconnect flows in the dashboard and authenticated API.
- Keeps extensions declarative. Packages can define bounded content models but
  cannot execute third-party code in the CMS process.
- Adds atomic content-bundle export and create-only import for moving selected
  collections and entries between CodeY CMS installations.
- Supports forward and cyclic relations during content import while preserving
  entry revisions and rejecting unsafe, oversized, or conflicting bundles.
- Extends public collection queries with bounded typed filters and deterministic
  sorting.
- Adds catalog provenance, lifecycle receipts, integrity checks, compatibility
  planning, and explicit operator trust for uncatalogued mounted extensions.
- Advances the builder registry to `2026-08-25.1` with glass interface, kinetic
  product, and floating product banner patterns. WebsiteSpec intake accepts the
  same bounded banner variants used by the shared server renderer.

## Compatibility

- WebsiteSpec remains at version `1.0`.
- Exported-site acceptance remains at version `1.0`.
- Extension manifests, catalogs, lifecycle receipts, and content bundles use
  their additive `1.0` contracts.
- Existing collections, entries, pages, posts, templates, shop data, and 1.1
  declarative extension manifests remain compatible.
- CodeY should discover runtime capabilities and builder registry
  `2026-08-25.1` from the signed CMS manifest. Users still receive the latest
  qualified stable CMS automatically and never select a CMS version.

## Database And Environment

Migration `20260825000000_extension_installations` adds the empty extension
installation receipt table. It does not rewrite existing content. The normal
signed update path applies it automatically.

No new environment variable is required. `CODEY_EXTENSIONS_DIR` remains an
optional operator-level directory override; packages mounted there are treated
as explicitly trusted by that operator.

## Upgrade Notes

Create a verified backup, then update through the signed stable release path.
After upgrading, confirm the Extensions and Collections pages load, inspect an
extension plan before installation, and verify a small content-bundle
export/import in a disposable site. Release qualification must continue to
prove signed installation, WebsiteSpec import, admin editing, restart,
server-rendered public output, encrypted backup/restore, and update rollback.
