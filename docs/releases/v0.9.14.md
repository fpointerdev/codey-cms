# CodeY CMS 0.9.14

CodeY CMS 0.9.14 adds a private, passwordless buyer order portal and makes the
signed runtime-upgrade qualification resilient when an Alpine package revision
used by the previous stable ZIP has left the upstream package index.

## Highlights

- Adds the noindex `/account/orders` storefront route with an HTTP-only,
  device-scoped buyer session.
- Lets buyers follow delivery progress, open safe tracking links, request help
  or cancellation, and forget the current device without creating an account.
- Links completed checkouts to the current browser and supports securely adding
  an order from another device with its private receipt credential.
- Adds merchant tracking and support-request controls to the order dashboard.
- Extends customer export and anonymization to buyer-session, tracking, support,
  payment, notification, and webhook metadata without touching unrelated users.
- Keeps buyer lookup credentials hashed at rest and exposes them only in the
  private receipt flow.
- Keeps Alpine packages pinned by default while exposing their recorded
  revisions as controlled Docker build arguments.
- Records any verified package-pin refresh used to boot the previous signed ZIP
  during update and rollback qualification. Unexpected package or Dockerfile
  shapes fail the release instead of bypassing qualification.

## Compatibility

- WebsiteSpec, builder, and exported-site acceptance contracts remain at
  version `1.0`.
- Existing CodeY-generated sites and CodeY CMS `v0.9.12` data remain compatible.
- Payment, email, storage, buyer-session, and order data remain owned by the
  generated site and are never added to WebsiteSpec.
- The signed runtime metadata retains the `v0.9.7` automatic-update bootstrap
  floor.

## Database And Environment

This release includes the `20260817000000_buyer_order_portal` migration. It
creates buyer sessions, order memberships, delivery tracking, and support-case
records. Existing orders are not modified or automatically attached to a
browser.

No new environment variable is required. The package-version build arguments
have secure recorded defaults and are used automatically by the official
installer and release qualifier. Production startup applies the migration
through the existing `prisma migrate deploy` path.

## Upgrade And Recovery Notes

Create a verified backup before updating. Existing buyers can add an earlier
order only when its receipt contains a private lookup credential. Keep the
configured credential-encryption key until queued receipt notifications have
been delivered; persisted lookup-token hashes do not depend on that key.

After upgrading, smoke-test checkout, **View your order**, tracking, support
requests, and **Forget this device**. The official release gate installs the
previous signed ZIP, verifies a successful update, forces a candidate failure,
and requires the previous runtime and server-rendered content to be restored.
