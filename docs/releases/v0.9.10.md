# CodeY CMS 0.9.10

CodeY CMS 0.9.10 is a focused recovery-safety release. It corrects the
previous-stable rollback path found by the extracted-package release qualifier
before 0.9.9 was published.

## Highlights

- Limits each PostgreSQL backup to the application schema selected by
  `DATABASE_URL` and records that schema in the backup manifest.
- Rejects restoring a schema-bound backup into a differently configured schema.
- Removes migration objects introduced by a failed candidate before replaying
  the pre-update archive.
- Performs automatic schema replacement and restore in one transaction so a
  failed replay does not leave an empty application schema.
- Lets a signed candidate that fails before readiness restore the exact backup
  bound to its applying update before the previous supervisor completes the
  runtime rollback.
- Keeps unrelated schemas out of the backup and untouched during restore.
- Adds a real PostgreSQL regression covering a future-version foreign key,
  rollback to the previous schema, and unrelated-schema isolation.

## Compatibility

- WebsiteSpec remains at version `1.0`; CodeY should continue selecting the
  latest verified signed stable release without asking users to choose a CMS
  version.
- Existing CodeY CMS `v0.9.8` installations remain supported by the packaged
  automatic update path; the signed runtime metadata retains the `v0.9.7`
  automatic-update bootstrap floor.
- Existing backup manifests without a schema field remain readable. New
  backups bind restores to their configured PostgreSQL schema.
- Payment and email provider credentials remain encrypted dashboard settings;
  they do not belong in WebsiteSpec or generated environment files.

## Upgrade Notes

No manual database step is required. Create a verified backup, then update from
the dashboard or start the new self-host package. The release workflow qualifies
both a successful update and a forced failed-candidate rollback using extracted
downloadable artifacts before publication.
