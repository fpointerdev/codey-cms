# CodeY CMS 1.1.0

CodeY CMS 1.1.0 adds first-class custom content modeling and a safe extension
foundation while deepening the stable visual design system introduced in 1.0.

## Highlights

- Adds dashboard-managed custom collections for people, locations, events,
  resources, directories, and other repeated structured content.
- Supports drafts, scheduled publishing, localization, revision restore, public
  read controls, bounded relations, uploaded assets, and typed entry forms.
- Adds validated email and HTTP(S) URL fields alongside text, rich text,
  numbers, dates, choices, relations, images, and files.
- Adds declarative content-model extension packs that install atomically without
  executing third-party server code.
- Publishes the versioned extension JSON Schema and a path-aware validator with
  machine-readable JSON output for extension repositories and CI systems.
- Advances the additive builder registry to `2026-08-24.1` with liquid and
  elevated card surfaces, bounded corner and hover styles, sidebar layouts,
  expanded component presentations, and CSS-only entrance effects that respect
  reduced-motion preferences.
- Adds a restrained liquid design preset shared by the dashboard preview,
  generated frontend, and server renderer.
- Uses the neutral `CodeY CMS contributors` identity in newly built package,
  legal-notice, and container metadata.

## Compatibility

- WebsiteSpec remains at version `1.0`.
- Exported-site acceptance remains at version `1.0`.
- The public API remains under `/api/v1`; its generated inventory reports CMS
  version `1.1.0`.
- Existing pages, posts, templates, sections, builder elements, and shop data
  remain compatible.
- Extensions using email or URL fields must require CodeY CMS `>=1.1.0`.
- CodeY should discover builder registry `2026-08-24.1` at runtime and continue
  selecting the latest signed stable CMS automatically.

## Database And Environment

This release adds the `CmsCollection`, `CmsCollectionEntry`, and
`CmsCollectionEntryRevision` tables through migration
`20260824000000_custom_content_collections`. The normal signed update path runs
the migration automatically. Existing content is not rewritten.

No new environment variable is required. Extension packs remain declarative
files, while installed collection models and entries are stored in PostgreSQL.
`CODEY_EXTENSIONS_DIR` remains an optional operator-level directory override.

## Upgrade Notes

Create a verified backup, then update through the signed stable release path.
After upgrading, confirm the Collections page loads, create one draft entry,
and publish it through the public collection API. The release qualification
must still prove signed installation, WebsiteSpec import, admin editing,
restart, server-rendered public output, backup/restore, and upgrade rollback
before publication.
