# CodeY CMS 1.6.0

CodeY CMS 1.6.0 improves safe client editing, owner handover and recovery while
keeping WebsiteSpec imports and customer-owned provider settings compatible.

## Changes

- Adds optional protected page/post editing. Content editors can update existing
  copy and media without changing the approved layout; design and publishing
  permissions remain separate and are enforced by the API.
- Rejects stale protected-content saves atomically. Failed edits remain in the
  form, and cross-editor refreshes do not discard unsaved settings.
- Distinguishes catalog, quote, test, live, manual, mixed and unknown commerce
  configuration. A configured provider is not presented as a verified payment.
- Recovers from interrupted setup and failed automatic sign-in without asking
  owners to install again. Browser storage is optional for session hints;
  authentication credentials are not stored there.
- Adds working settings deep links and a downloadable owner handover report.
  Reports explicitly separate configuration from public delivery and recovery
  evidence. Detailed readiness requires management access.
- Adds admin-only encrypted backup requests through the existing worker, with
  job IDs, completion status, cooldown, fresh heartbeat checks and shared backup
  locking. Requests during a scheduled snapshot queue their own encrypted job.
- Stops application writes before the update recovery snapshot, preserving the
  last accepted edits when a candidate must roll back. A failed pre-update
  backup restarts the unchanged runtime.
- Documents the canonical managed-hosting requirements, including isolated
  candidates, provider egress restrictions, write-fenced snapshots and safe
  cutover. This release does not implement CodeY managed hosting or deploy MCP.

## Compatibility

WebsiteSpec and exported-site acceptance remain `1.0`. The builder registry is
unchanged. Protected editing is opt-in; existing roles are not silently granted
design or publishing privileges. Existing customer payment, email, storage and
marketing settings remain in the database and are not imported through WebsiteSpec.

Generation discovery adds `contentEditing`, `commerceReadiness` and
`ownerHandover` capabilities, each version `1.0`. Generators must discover these
from the installed runtime before exposing them. The detailed launch-readiness
endpoint now requires `manage:modules`; minimal anonymous health remains available.

## Database And Environment

No database migration, new dependency or environment variable is required.
Provider credentials and encryption/signing trust boundaries are unchanged.

## Upgrade Notes

Create a verified encrypted backup and preserve all existing named volumes and
the installation's Compose project name. Refresh the signed self-host package
and recreate its backend and backup services to adopt the supervisor ordering
fix and backup request worker. An application-only automatic update does not
replace the running supervisor or the standalone backup container.

Use the existing deployment's reviewed Compose configuration and overrides;
do not start a second generic project over an exported or customized installation.
Never run `down --volumes`, reset the database, or repeat owner setup to upgrade.
Until its worker is refreshed, the new dashboard backup action reports unavailable.

The backup button does not restore a live database or establish off-site
protection. Keep an independently protected copy and test recovery on an isolated
instance. A crashed backup lock must be inspected by the operator before removal.

## Verification

Focused tests cover permission boundaries, atomic conflicts, retained content,
setup recovery, backup job concurrency/encryption and update rollback ordering.
Publication requires the normal hosted source, API/database, browser, public
quality and extracted-package gates, followed by signed package verification
and previous-stable upgrade/forced-rollback qualification.
