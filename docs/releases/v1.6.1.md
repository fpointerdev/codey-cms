# CodeY CMS 1.6.1

CodeY CMS 1.6.1 hardens the self-host runtime and its release supply chain while
preserving customer content and the existing generation contracts.

## Security

- Updates vulnerable server, MCP, browser-bundle, and package-manager dependencies.
  Production audits include bundled dependencies even when they are build-time
  dependencies in the repository.
- Prevents bcrypt password truncation by limiting new passwords to 72 UTF-8
  bytes. Existing password hashes and logins remain valid.
- Limits authentication/install JSON to 16 KB, ordinary API JSON to 256 KB,
  and payment webhooks to 1 MB. Large content/import/upload requests authenticate
  before parsing. Compressed request bodies are rejected; response compression
  and webhook signature verification remain enabled.
- Separates the public API from migration and backup credentials. API mounts
  for runtime releases and backup archives are read-only. Private workers
  perform migrations, encrypted snapshots, and signed updates.
- Hardens update staging, worker status writes, and interrupted secret setup.
- Pins current container inputs and removes unused package-manager tooling.
  PostgreSQL keeps version 16 and its data directory, with patched XML parsing
  and Alpine's smaller privilege helper.
- Builds standard Caddy 2.11.9 against an exact upstream Smallstep migration
  to patched JOSE v4 and the patched Go networking library. No vulnerability
  exclusions or certificate-validation bypasses are introduced.
- Requires shipped-image vulnerability and verified-HTTPS qualification before
  release publication. Major dependency fixes are no longer hidden from Dependabot.

## Compatibility

WebsiteSpec, exported-site acceptance, generation automation, and the builder
registry remain compatible. Zod 4 validation preserves omitted PATCH fields
and nested creation defaults. No database migration or password reset is needed.
Payment, email, and storage settings remain customer-owned dashboard settings.

## Required Self-Host Update

Take and verify an encrypted backup, wait for any runtime update to finish,
then refresh the signed package and recreate the services using the existing
installation directory, Compose project name, and named volumes. The launcher
builds the patched proxy/database images and configures the private workers.
The first image build can take several minutes.

A runtime-only automatic update cannot replace container mounts or Caddy. Keep
generated WebsiteSpec mounts on `backend`. Move any backup-mirror override from
`backend` to `supervisor`, keeping the mirror on `backup` too. Custom deployments
must preserve the new service boundaries. See [installation](../self-host-installation.md).

Do not remove volumes, reset the database, rotate existing secrets, or repeat
owner setup. Internal backup-control configuration is supplied automatically;
customers do not need to manage new keys or choose dependency versions.

## Verification

Publication requires source and coverage gates, dependency/image audits,
installation/integration/recovery/browser/public-quality checks, verified TLS,
extracted-package acceptance, signed artifact verification, and the previous
stable upgrade plus forced-rollback qualifier.
