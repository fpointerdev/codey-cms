# CodeY CMS 0.9.13

CodeY CMS 0.9.13 adds a private, passwordless buyer order portal to the
canonical storefront. Buyers can follow orders, see delivery tracking, request
help, and manage cancellation without creating an account. Existing sites keep
their content, commerce settings, and generated design unchanged.

## Highlights

- Adds the noindex `/account/orders` storefront route with an HTTP-only,
  device-scoped buyer session.
- Keeps the buyer route CMS-owned when a custom storefront is active, preventing
  a generic SPA fallback from hiding order history.
- Links completed checkouts to the current browser and lets buyers securely add
  an order from another device using the private credential in its receipt.
- Adds buyer-visible delivery progress, tracking links, cancellation handling,
  complaints, returns, and other support requests.
- Adds merchant tracking and support-request controls to the order dashboard.
- Adds a visible **Forget this device** action that removes the current buyer
  session without changing the order.
- Extends customer export and anonymization to tracking, support, buyer-session,
  payment, notification, and webhook metadata without touching unrelated
  sessions.
- Keeps order lookup credentials hashed at rest and encrypted only while a
  receipt notification is waiting for delivery.

## Compatibility

- WebsiteSpec, builder, and exported-site acceptance contracts remain at
  version `1.0`.
- Existing CodeY-generated sites and CodeY CMS `v0.9.12` data remain compatible.
- Payment, email, storage, buyer-session, and order data remain owned by the
  generated site and are never added to WebsiteSpec.
- The signed runtime metadata retains the `v0.9.7` automatic-update bootstrap
  floor.

## Database And Environment

This release adds the `20260817000000_buyer_order_portal` migration. It creates
buyer sessions, order memberships, delivery tracking, and support-case records.
Existing orders are not modified or automatically attached to a browser.

No new environment variable is required. Production startup applies the
migration through the existing `prisma migrate deploy` path.

## Upgrade And Recovery Notes

Create a verified backup before updating. Existing buyers can add an earlier
order only when its receipt contains a private lookup credential. Keep the
configured credential-encryption key until queued receipt notifications have
been delivered; persisted lookup-token hashes do not depend on that key.

After upgrade, smoke-test checkout, the **View your order** link, tracking,
support requests, and **Forget this device**. A rollback to `v0.9.12` ignores
the additive tables; preserve their records in backup if buyer portal activity
has already started.
